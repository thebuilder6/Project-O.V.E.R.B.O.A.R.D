# Round 1 — verification (Gatekeeper Gus)

[GRIEVANCE] `overboard/main.py:2002-2012` + `main.py:174-185` — early-stop contradicts score-based selection. `_run_candidates` validates in duration order and marks every slower candidate `validation_skipped` (score stays `None`, never eligible) once a faster one passes. But `_select_attempt_scored` picks the highest decision score, not the fastest — under `balanced`/`speed` profiles a slightly slower but much cleaner candidate can outscore the fastest passer and is never even checked. The gate thus selects "fastest passer," not "best score," while the JSON claims a score decision. Minimal fix: when `validate` is on, run with `early_stop=False` (pay the extra validations), or only skip candidates whose fitness upper bound cannot beat the current best score.

[GRIEVANCE] `overboard/main.py:1649-1669,2374-2391` — field-clearance gate prices nominal geometry while recording ~100 mm placement uncertainty it never applies. `raw <= 0` (nominal body inside a model) is structural, but a nominal clearance of e.g. 10 mm passes the `util > 1` physical gate while the true clearance may be −90 mm. The accuracy channel has the same optimism before clamping to 5–50 mm. A pass near a mission model is therefore evidence against the drawing, not the field. Minimal fix: deflate each raw clearance by `placement_uncertainty_m` (floor at 0 for the accuracy clamp input, allow negative into the structural check) before `util`/clamp.

[QUESTION] `overboard/main.py:549-564` (`_local_limit`) — the per-metre allowance is added to waypoint-declared limits too (`_envelope_limit_at(declared, per_metre, travelled_at)`). A 5 mm `precision_mode` waypoint 4 m into a path with `--envelope-limit-per-metre 0.005` is judged at 25 mm, which silently un-declares the precision the operator asked for and weakens exactly the KI-054 control the flag was added to provide. Is that intended? Minimal fix: keep declared waypoint limits absolute; apply `per_metre` only to the run-wide default fallback.

[SUGGESTION] `overboard/verification/reachability_engine.py:228-236` + `immrax_validator.py:1193-1209,244-260` — the tube starts from an assumed ±1 mm pose box, and the plant docstring concedes the DriveBase PID and whole-millimetre distance quantisation are unmodelled (KI-020). A hand-placed robot's start error can exceed the entire initial tube, so every downstream width inherits an unjustified optimistic prior. Minimal fix (no model change): expose the initial box half-width as a validator parameter defaulting to 0.001, sourced from the placement-uncertainty figure where a field model exists, and state the PID/quantisation residual alongside the pass verdict.
