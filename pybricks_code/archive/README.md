# Archived firmware scripts

These are kept for reference and are **not** part of the supported robot
surface. `tests/test_hub_deploy.py::TestFirmwareCompiles` compiles every
`*.py` in `pybricks_code/` but does not descend into this folder, so these
files are not compiled or pushed by anything.

| File | Why it is here |
|---|---|
| `mission_1_simple.py` | Teaching demo (DriveBase primitives), superseded by a pushed trajectory. |
| `mission_2_async.py` | Teaching demo (`multitask`), superseded by a pushed trajectory. |
| `mission_3_advanced.py` | Teaching demo (competitive run), superseded by a pushed trajectory. |
| `mission_4_ramsete.py` | Demo runner for `complex_mission.py`; the host pushes `hub_runner.py` instead. |
| `mission_5_lambdas.py` | Demo runner for `complete_mission.py`; its event-map idea lives in `hub_runner.MISSION_EVENTS`. |
| `mission_template.py` | Blank template for the demos above. |
| `complete_mission.py` | Generated by `--export-format python`; only `mission_5_lambdas.py` imported it, and it fails the validation gates by design. |
| `sysid_data_logger.py` | The older telemetry collector, superseded by `sysid_digital_twin.py`. |
| `plot_tracking.py` | Host-side matplotlib script (not firmware) for the `LOG,` lines; never pushed to a hub. |

`complex_mission.py` is **not** archived: `sysid_digital_twin.py` replays it as
its held-out check, so it stays in `pybricks_code/`.

To revive one of these, move it back next to `robot_config.py` and make sure
whatever it imports still exists.
