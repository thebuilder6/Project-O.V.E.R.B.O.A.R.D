# AGENTS.md

Python CLI/library for time-optimal trajectories of a LEGO/FLL differential-drive robot (CasADi + IPOPT), plus robot-side Pybricks code. Flat modules, no packaging: run every command from the repo root.

This file is the index: the rules, the entry points, and where the rest lives. Detail - measurements, thresholds, feature tours, the reasons a rule exists - is in `docs/AGENT_OPS.md`, one section per topic; read only the section a task needs.

## Read first

- `KNOWN_ISSUES.md` is the source of truth for risky paths. Open: KI-004 (the seed provider), KI-020 (hardware calibration and digital-twin validation). Mitigated: KI-032 (the test cache). Everything else in KI-001..KI-052 is fixed. Cite KI IDs; do not silently "fix" an open one unless asked. Read the **Quick triage** table at the top - one line per entry - and open an entry only when you are working on it; the entries below it are the history.
- `--validate` is a hard gate, and the validation model is not yet a full digital twin (KI-020).
- `docs/HEURISTICS_AND_VERIFICATION.md` before changing the initial-guess seeds, the timing models, the candidate set, the selection rule or the validation thresholds - it holds the strategy ledger, so do not re-litigate a failed strategy without new evidence. Start at "Findings at a glance" and its table of contents, not page one. Same for `docs/research/RQ-A_tracking_error.md` before changing the optimizer's kinematics, the reference interpolation, the tracking gate or its 5 mm threshold - its "short answer" is the part you need.
- The Multi-Verse pipeline is a **seed provider**, not a second solver: `--refine` puts its refined trajectory into the candidate set, and it is opt-in (KI-004). Where a doc and the tree disagree, the source is the authority.

## Commands

- Install the core path: `pip install -r requirements.txt` (solver and studio). `--validate`, `--multiverse` and `--push-hub` also need `pip install -r requirements-optional.txt` (jax, jaxopt, immrax, pybricksdev). `install.bat` / `sh install.sh` builds `.venv` with both and runs the check; `start_studio.bat` / `sh start_studio.sh` start the studio with it. The `.bat` files must keep CRLF line endings (`cmd.exe` cannot find a batch label in an LF file) and the `.sh` files must stay LF. §Install.
- `python main.py --doctor` reports the Python version, every package, the example files, the output directory and the ports, with the install command for anything missing. Run it first when something does not work.
- Quick, predictable run:
  `python main.py -w examples/example_straight.json -o output.traj`
- The simple CasADi solver is the default **backend**; `--unified` (the default) selects the 3-Pillar engine on top of it, and `--no-unified` restores the stock candidate set. `--multiverse` selects the deprecated pipeline and `--simple` is a deprecated alias. `--force-weight` is refused by `--multiverse`; the other *simple solver only* flags are not read there.
- `--refine` (simple solver only, needs JAX) adds the seed provider's refined trajectory to the candidate set. Off by default: it is a cheaper way to reach the stock set's speed, not a better one, and it rescues nothing (KI-004). §Solve options.
- The candidate set mixes the two timing modes - equal-duration baseline first, per-segment baseline second, then the remaining seeds alternate. `--candidates N` (default 2, max 5) sets the count; `--uniform-dt` / `--per-segment-dt` force one mode. The per-segment mode is the general model (equal `dt_i` recovers the equal-duration solution), and both are held to the same wheel-jerk discipline, so `--accuracy-weight` means the same thing in either (KI-022). **Do not force a mode silently.**
- A waypoint is a timing boundary only when the robot stops there AND the heading is pinned; elsewhere the pieces stay linked and the per-segment model requires the wheel acceleration - and so the wheel force - to be continuous through the point (KI-024). `TrajectoryOptimizer.merge_conditions(waypoints, stop_waypoint_indices=None)` is the one place that rule lives.
- When a run produces nothing usable the CLI tries the other seeds as a rescue before giving up, and a rescue candidate is selected only when the candidate set itself produced nothing that passed (KI-048). It costs nothing when the plan works.
- The opt-in solve paths, all off by default: `--fast-polish` (200-iteration warm budget, cold finish, fallback to the unbudgeted pass, KI-047), `--sweep` (the timing-mode x accuracy-weight grid - ten candidates instead of two), `--force-weight` (prices wheel-force utilisation instead of only bounding it) and `--surrogate-polish` (5-layer surrogate-to-truth). `--unified` is the **default** path (3-Pillar Unified Trajectory Engine); `--no-unified` restores the stock candidate set, and it steps aside automatically for `--uniform-dt`, `--sweep`, `--refine` or `--multiverse` unless `--unified` is explicit. Do not enable an opt-in path silently. §Solve options.
- The optimizer also takes three parameters the command line does not expose: `cost_metric` (`"jerk"` or `"discretization"`), `epigraph_constraints` and `sample_weights`. `TrajectoryOptimizer.solve` reads them. §Solve options.
- `--preset fast|balanced|safe` fills in only the options the user did not set: fast = 1 candidate without validation, balanced = the defaults, safe = 3 candidates with `--validate` and a controller export. Explicit flags always win.
- `--validate` gates every output and the exit code, and requires JAX/Immrax. It solves the candidate set (parallel when validating), validates each, and selects a passing one by the lowest 5-part path fitness score (stop spread, slip risk, RMS wheel force, tracking error, run time; envelope and duration break ties). The score needs the Immrax report, so without one the rule is smallest envelope, then shortest duration. Without `--validate`, only the first candidate is solved. **If validation fails, no `.traj`, controller, Python file or `_stats.json` is written.** §Validation.
- `--propagation [plant|tick]` picks the reachability model the envelope gate uses (KI-049, KI-050). "plant", the default, propagates the plant open-loop with the controller evaluated outside the tube; "tick" embeds one closed-loop tick, so the tube contracts like the robot's - it needs a Jacobian inclusion and costs 2-3x (`jac`) to 7-10x (`mjac`) the validation time. `research/harness.py` takes the same flag. **An envelope is never read without its model**: every candidate carries `propagation` and `inclusion`. §Validation.
- `--validate --export-format controller` writes `<output>_controller.json`; `python` writes `<output>.py`; `python-compact` writes the packed module for `ramsete_compact.py` / `ramsete_compact_events.py`; `--benchmark` writes `<output>_stats.json` after the export gate.
- The hub path is `--push-hub` (writes `pybricks_code/hub_mission.py`, pushes `hub_runner.py`; `--hub-conn ble|usb`, `--hub-name`, `--hub-log`), `python hub_deploy.py <script.py> [--out session.csv]` for any script, and `python sysid_collect.py --conn ble` for the one-command SysId loop. Bluetooth discovery goes through `hub_ble.py` (KI-033); `hub_deploy.py --list-hubs` is the device picker. It needs `pybricksdev`; a plain solve never imports it. §Export.
- Browser studio: `python main.py --gui` (port 8000 on `127.0.0.1`, `--gui-port`, next free port if busy). It serves `viz/studio.html` from `gui_server.py`, runs the CLI in a subprocess and **never bypasses the export gate**; it uses the simple solver only and runs one solve at a time (`GET /api/jobs/current` attaches). Its push button is gated on the *validator's* verdict. `docs/STUDIO_UI_INVENTORY.md` + `tests/test_studio_inventory.py` must stay in step with the markup. §The browser studio.
- With `--validate`, `main.py` prints one machine-readable line per run: `##OVERBOARD-VALIDATION## {json}` with the per-candidate and per-segment envelope, limit, drift, reasons, the accuracy weight of each candidate and its score vector (`duration_s`, `envelope_cm`, `tracking_cm`, `max_excess_cm`, `peak_jerk_m_s3`, `fitness_s` and its parts), so the selection rule can be re-run offline. **Keep the JSON valid** (`Infinity` breaks `JSON.parse`); nothing is written to disk on a failed validation, so the report goes to stdout only.
- `docs/CALIBRATION_PROCEDURE.md` is the human procedure; `docs/CALIBRATION_STUDIO_PLAN.md`, `docs/STUDIO_HUB_PLAN.md` and `docs/STUDIO_3D_SIMULATOR_PLAN.md` are the designs for the studio's sysid loop, its push-to-hub and the 3D simulator. Calibration-critical tests run three times with the step order reversed on every other repeat and a 95 % t-interval per parameter; the drift is a **slope, not a subtraction**; the motor's stall torque and no-load speed are measured and written into the robot config, so every tool plans against the same motor (KI-010). §Calibration.
- Tests: `python run_tests.py` (687 tests with JAX installed). Single test: `python -m unittest tests.test_optimizer.TestTrajectoryOptimizer.test_init -v`
- Cross-check: `python research/crosscheck/compare_step.py` against an independent rigid-body simulator (WSL2; `research/crosscheck/README.md`). Measurement code, changes nothing in the planner.
- Stress run: `python research/suite.py --count N --seed S --out DIR`, then `python research/harness.py --missions DIR --out FILE`, read back with `python research/analyze.py errors|robots FILE`; pin the tree with `OVERBOARD_TREE` while editing. Benchmarks: `python benchmark.py --mode pipeline|cli|random|solver` (default config `examples/fll_choreo.json`) - all four work (KI-015), and `--mode solver` is the reference table for a solver change. §Research.
- `--plot`, `--animate`, `--gui` and `--live` are blocking; keep automated runs headless.

## Test quirks (verified)

- `run_tests.py` imports the JAX test modules in a `try`; without JAX it prints a warning and skips them. With JAX the suite is 687 tests, 0 skipped.
- The runner holds an **explicit list of the test classes it runs** (`test_classes()`), so a class that is not in the list never runs. `tests/test_suite_registry.py` checks that every test class in `tests/` is listed.
- The suite keeps a **test cache** (`testcache.py`, `.test_cache.json`, gitignored). A test that PASSED is skipped when nothing it reads has changed; a failure always runs again, and a test that wrote a file inside the repository is never skipped. The cache never decides that a test passed - it only says a test does not have to run again. `--cache-status`, `--no-cache`, `--clear-cache`, `--durations 20`. Measured 121 s cold, 20 s warm (KI-032). §Research.
- The old `test_stomp_variants.py` and `test_teb_topologies.py` modules are deleted. Do not reintroduce tests for removed `MultiVerseRefiner` / `LocalSegmentOptimizer` classes.
- JAX/refinement modules: `python -m unittest tests.test_jax_heuristics tests.test_jax_ramsete tests.test_refinement_accuracy tests.test_critic_metrics`
- `tests/test_cli_ux.py` and `tests/test_gui_server.py` cover the CLI surface and the studio server (a real server on an ephemeral port and one real solve). `tests/test_studio_honesty.py` pins what the studio owes the operator (the push needs a validated trajectory, a failed solve leaves no path on the field, an error carries no internal path, `hidden` actually hides - KI-030).

## Architecture and contracts

- `main.py` is the only CLI entry point. It defaults to `TrajectoryOptimizer` (CasADi/IPOPT); `--multiverse` selects `MasterTrajectoryOptimizer`, whose refinement is **segment-preserving**: the unit is one segment, its endpoints are waypoints and are kept exactly. §Planner internals.
- `TrajectoryOptimizer.solve` **splits the path** at the waypoints where the robot stops AND the heading is pinned, solving each piece as its own NLP and keeping the cheapest seed. Opt-out (`split_at_boundaries=False`).
- The **sample count follows the path**: `get_segment_sample_counts` splits the budget in proportion to arc length (at least three samples each), and `waypoint_sample_indices` / `stats["segment_samples"]` map a sample back to its waypoint. Seeds and the objective follow that layout, so a measurement must say which layout it was taken on.
- `--self-consistent` is the default everywhere (CLI and `TrajectoryOptimizer.solve`); `--no-self-consistent` restores the trapezoidal rule. The position rule integrates with four-node Gauss-Legendre along the integrated heading, so the samples lie on the path the plan's own (v, omega) profile traces (KI-026, KI-051, KI-052). §Planner internals.
- The reference interpolates heading, speed, turn rate and Ramsete gain as independent lines, but they are coupled: the turn rate must be the derivative of the interpolated heading and the gain `sqrt(w^2 + b*v^2)` of the interpolated values. All five controller modules and `immrax_validator.py` do that, and the heading difference is taken the short way, as the firmware does (KI-027).
- The validator models the controller that **runs** (synced 20 ms heartbeat, floats to `drive()`, no rounding - KI-027, KI-028), and **there is one implementation in the firmware**: `ramsete.py` holds the odometry, the Ramsete maths and the loop; `ramsete_fast.py` delegates to it and `ramsete_compact.py` delegates to `ramsete_compact_events.py` with events off. `tests/test_firmware_events.py::TestFirmwareParity` pins it. The firmware `KinematicLimiter` uses the per-wheel traction limit with lateral weight transfer and the robot's own fallback numbers, and applies no backlash: backlash is a position uncertainty in the reachable set (KI-025), never a velocity offset. §Planner internals.
- The validator has two propagations (`PROPAGATION`): "plant" is the default, "tick" is opt-in. The tick map needs the mixed Jacobian inclusion and the pose must be read by indexing, never unpacked (`x, y, theta = pose` is `unstack`, which has no inclusion rule). §Validation.
- `robot_model.py` parses the canonical `{"robot": {...}}`, legacy Choreo `{"config": {k: {"val": ...}}}` and flat dicts identically, including `robot.uncertainties`; `JAXRobotConfig` delegates to `RobotConfig` (KI-008).
- The optimizer and validator share one per-wheel force model (`wheel_normal_forces`): lateral weight transfer only, no front/rear split; Immrax uses the same ranges (KI-009, KI-010).
- Heavy imports are lazy: a simple solve must not import JAX, Immrax, Multi-Verse or the plotters. `main.ImmraxValidator` and `main.JAXRobotConfig` stay at module level (`None` until `_ensure_jax_classes`) so tests can patch them.
- Waypoints are dicts or `[x,y,heading]`, optional `stop`, `event`, `error_threshold`, `precision_mode`. An event on the final waypoint lands on the last sample and fires after the loop, once the drivebase has stopped (KI-012).
- Output is Choreo v3 (`trajectory.samples`). Keep the sample schema (`t,x,y,heading,vl,vr,omega`, forces, optional `event` / `reachability_envelope`) stable: validator, exporter, plotters and the Pybricks runtime consume it.
- `pybricks_code/` is firmware, not CPython (`pybricks.*`, `umath`); do not run it on the host. `complex_mission.py` / `complete_mission.py` are generated by `--export-format python` - regenerate, do not hand-edit (KI-018). §Planner internals.
- MicroPython cannot concatenate two f-strings: build output with one `%` format or one f-string per statement. `tests/test_hub_deploy.py::TestFirmwareCompiles` compiles every file in `pybricks_code/` with mpy-cross.
- The hub-to-host contract is the session format: `TEST_START <name>`, `META,key,value`, a `DATA` block with a `t_ms,...` header, `TEST_END,<n>`; a test reports `POSE,x_m,y_m,heading_deg` and `EVENT,name`, and a pose takes the run id of the test that was open. Never break those line formats; the planner's heading is counter-clockwise positive while `drivebase.angle()` is clockwise positive.
- `hub_runner.py` is the only hub entry point for a pushed trajectory: it imports the generated `hub_mission.py` (gitignored) and the hardware from `robot_config.py`, and returns the final odometry pose. Event actions live in the runner's `MISSION_EVENTS`; `robot_config.py` stays hardware-only.
- Root-level `.traj`, `*_controller.json`, `*_stats.json` and `test_output*` are generated artifacts, not source. `sysid_fit.py` is host-side; it never runs on the Hub.
